Cloudflare Tunnels (Túnel Web Público Gratuito): Expone tu frontend y backend a internet mediante un enlace web HTTPS público sin abrir puertos ni pagar dominio, ideal para que cualquier persona acceda desde su navegador sin instalar nada y aprovechando tu propio sistema de login, aunque para la telemetría en tiempo real requiere usar MQTT sobre WebSockets (puerto 9001).

Conexiones y NAT

Cómo funciona: los clientes MQTT (gateways/dispositivos) inician la conexión TCP/WS hacia el broker; eso atraviesa NAT/firewalls salientes, por lo que no hace falta exposición inversa en cada planta.
Requisito: el broker debe ser alcanzable desde Internet (IP pública o DNS) o los dispositivos deben poder alcanzar la IP privada vía VPN (p. ej. Tailscale).
Seguridad

TLS: usar MQTT sobre TLS (puerto 8883) o MQTT sobre WebSockets + HTTPS (9001/443) para cifrar tráfico.
Autenticación: credenciales por device/gateway; evitar usuarios genéricos.
ACLs: definir reglas que restrinjan publish/subscribe por prefijo tenant (ej.: plantaA/#), por usuario y por topic. Revisa mosquitto.conf:1-40 para password_file/acl_file.
Disponibilidad y resiliencia

Conectividad inestable: usar QoS 1 (o 2 si es imprescindible), sesiones persistentes y LWT para detectar offline; implementar buffering local en el gateway para reenviar tras reconexión.
Edge vs Central: si la planta puede perder Internet, mejor poner un broker/edge local + sincronizar al central después (bridge o push REST). Si las plantas siempre tienen conectividad estable, un broker central es suficiente.
Protocolos y túneles

Broker central + clientes remotos: recomendado si abrís puerto 8883/9001 y protegés con TLS/ACL.
Túneles (Cloudflare/ngrok): útiles para demos; para MQTT nativo necesitas túnel TCP o usar WS (9001).
VPN (Tailscale): excelente para seguridad y para permitir MQTT nativo sin abrir puertos públicos.
Escalado

Un único broker soporta muchas plantas si es dimensionado (EMQX/HiveMQ/EMQ Cloud). Mosquitto funciona bien para volúmenes medios. Monitorizar conexiones, throughput y uso de CPU/IO.
Integración con backend

El backend debe consumir tópicos relevantes (worker paho-mqtt o plugin broker) y persistir lecturas con el tenant/fabrica extraído del topic (ej.: tenant/gw/sector/sistema/device/var).
Garantizar idempotencia y timestamps en los mensajes para reconciliación.
Recomendaciones prácticas mínimas

Habilitar TLS en Mosquitto y exponer puerto 8883 (o usar WS sobre 443).
Crear credenciales por gateway y ACLs por prefijo tenant/….
Definir esquema de topics por planta: tenant/gateway/sector/sistema/dispositivo/variable.
Para plantas con conectividad intermitente, desplegar un edge service (broker local) que haga bridge/sync con el central.
Probar con simuladores (puedo generarlos) antes de pasar a producción.

- Integración de Visualización Geográfica / Mapas Interactivos (Multisitio)
Propuesta de factibilidad y diseño técnico para representar las ubicaciones de las fábricas en un mapa interactivo del sistema SCADA:
1. Complejidad: Media.
2. Proveedores y tecnologías candidatas:
   * Opción A (Recomendada - Open Source): Leaflet.js + OpenStreetMap. Es 100% gratuita, ligera y no requiere API keys ni configuraciones de facturación de terceros. Permite integrar marcadores dinámicos y popups de forma nativa en React.
   * Opción B (Comercial): Google Maps API. Ofrece gran detalle satelital y street view a costa de requerir una cuenta de Google Cloud y facturación de consumo mediante API Keys.
3. Plan de desarrollo técnico:
   * Backend: Agregar los campos float `latitud` y `longitud` al modelo `Fabrica` (con soporte para nulos) en Django y actualizar el serializador de fábricas.
   * Frontend: Agregar una pestaña de "Vista de Mapa" en el panel de Monitorización que renderice el mapa interactivo y coloque marcadores geográficos. El marcador cambiará de color según el estado en tiempo real de la planta (e.g. verde: Operativo, amarillo: Advertencia, rojo: Crítico). Al pulsar sobre el marcador, se despliega un popup con indicadores rápidos de producción y eficiencia junto con un botón para abrir su monitorización en detalle.
